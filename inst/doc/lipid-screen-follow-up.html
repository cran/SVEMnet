Choosing and confirming follow-up recipes in a 23-run lipid screen

The worked example fits elastic-net SVEM, forward-likelihood SVEM, GauPro and Extra Trees on the same experimental factors. The installed package includes the complete executable analysis, so the results can be regenerated with different measurements or a different preparation budget. To rerun it, copy the source to a writable project directory and render it there. Install the suggested packages GauPro and ranger to include both companions. The final sections use a two-factor teaching surface and an optional general spline on the full mixture/process experiment with its nominal ingredient factor. They show explicit model and exploration counts. The worklist reports how many distinct settings those models nominate. Install the suggested package mgcv for that section.

The GP fits in this example use one seeded optimizer start per endpoint. Rerunning with a different seed can lead to a different fitted surface and recipe nomination. Compare plausible nominees in the laboratory when that sensitivity affects the decision.

For a large recipe table, the optional medoid step compares pairs of high-spread recipes. Its memory cost grows with the square of the shortlist size. A discrete table of settings the lab can prepare keeps this step small.

Start with the 23 measured preparations in lipid_screen. The first example uses only the core package to export five distinct new preparations. It keeps the three response goals, mixture bounds, planned operator and run budget visible. The advanced example then adds other models, reserves an incumbent repeat within an eight-preparation budget, simulates measurements and refits. A separate two-factor process example at the end shows how to request a spline nominee and reserve distinct exploration preparations.

For another experiment, change the data, factor specification, goals and feasible candidate settings below. Keep one row per independent preparation; aggregate technical assay replicates before fitting. A repeated recipe in a new preparation is a new row with its own preparation ID.

For planning the initial mixture or process experiment, see Karl’s A Sphericity Filter for Space-Filling Designs in Nondeterministic Experiments. Its low-order working model protects selected estimation precision while retaining space-filling coverage. That design choice is separate from the richer cubic candidate model fitted below; it does not require the final response surface to be low-order.

Specify the experiment once

library(SVEMnet)
data(lipid_screen, package = "SVEMnet")
dat <- lipid_screen
components <- c("PEG", "Helper", "Ionizable", "Cholesterol")
recipe_cols <- c(components, "Ionizable_Lipid_Type", "N_P_ratio", "flow_rate")
predictors <- c(recipe_cols, "Operator")
mix <- list(list(vars = components, lower = c(.01, .10, .10, .10),
                 upper = c(.05, .60, .60, .60), total = 1))
spec <- bigexp_terms(
  Potency ~ PEG + Helper + Ionizable + Cholesterol +
    Ionizable_Lipid_Type + N_P_ratio + flow_rate, data = dat,
  blocking = "Operator", mixture_groups = mix,
  discrete_numeric = c("N_P_ratio", "flow_rate"), report = FALSE
)
goals <- list(
  Potency = list(goal = "max", weight = .6, lower_acceptable = 65, upper_acceptable = 95),
  Size    = list(goal = "min", weight = .3, lower_acceptable = 40, upper_acceptable = 210),
  PDI     = list(goal = "min", weight = .1, lower_acceptable = .04, upper_acceptable = .39)
)
endpoints <- names(goals)

The default bigexp_terms() expansion is a full cubic candidate model: pure squares and cubes, two- and three-factor interactions, and partial-cubic terms such as x^2:z. Blocking variables stay additive. The fitting method reduces this common candidate model; no preliminary choice of a smaller model is required.

Advanced: several models and a carried-forward reference

The SVEMnet paper starts with the same data, candidate terms and scientific weights. Its workflow fits each endpoint, scores feasible settings, chooses diverse high-score and high-uncertainty recipes, and refits after measurement. Here we also ask forward-selection SVEM, GauPro and Extra Trees to nominate recipes. The fixed publication did not benchmark these additions. The journal articles remain the versions of record; the author occasionally updates the SVEMnet arXiv manuscript and the earlier workflow arXiv manuscript.

What the Gaussian process contributes

This package implements a custom confirmation workflow. GauPro proposes a recipe using its fitted mean (or the desirability of several fitted means). A separate exploration slot can use the largest latent standard deviation for a chosen response. The scientist allocates preparations, measures them and decides when to refit. A full Bayesian optimizer specifies an acquisition policy for those sequential decisions. For example, expected improvement uses both the predicted improvement and uncertainty to choose a point. Jones, Schonlau and Welch (1998) and Frazier (2018).

SVEMnet offers the full candidate expansion and shrinks the additive operator effect. The two optional companions use the original factors and free mixture coordinates. Here we deliberately let those models learn operator-by-recipe patterns. Both operators handled every lipid type, but some combinations have little support. We specify operator A for every new preparation.

Prepare the candidate table before optimizing

The proportions below are built in integer basis points. The fourth component is determined by the total. The seed recipes are included in the candidate table so that an endorsement of a previous preparation can be recognized. The paper draws 25,000 feasible settings and derives default desirability anchors from predicted response quantiles. Here a smaller discrete pool and fixed anchors make the models and both rounds comparable. The resulting recipe IDs and scores are specific to this example. In practice, supply the full set of recipes the lab would prepare or draw a larger feasible pool.

composition <- expand.grid(PEG = seq(100, 500, 100),

stopifnot(all(abs(rowSums(pool[components]) - 1) < 1e-10))

# Map each preparation to a physical recipe ID, regardless of operator.
# Quantize only the mixture columns and reject off-grid inputs.
physical_settings <- function(rows) {
  key <- rows[recipe_cols]
  for (nm in names(increments)) {
    units <- key[[nm]] / increments[[nm]]
    stopifnot(all(abs(units - round(units)) <= 1e-7))
    key[[nm]] <- round(units)
  }
  key
}
lookup <- cbind(recipe_id = pool$recipe_id, physical_settings(pool))
stopifnot(!anyDuplicated(lookup[recipe_cols]))
screen_rows <- cbind(screen_row = seq_len(nrow(dat)), physical_settings(dat))
matched <- merge(screen_rows, lookup, by = recipe_cols, all.x = TRUE)
dat$recipe_id <- matched$recipe_id[match(screen_rows$screen_row, matched$screen_row)]
stopifnot(nrow(matched) == nrow(dat), !anyNA(dat$recipe_id))

Allocate eight preparations, including an incumbent repeat

The convenience function earns its place when several models and a reference are needed: it fits the endpoints, collects model nominees and delegates the allocation to the scorer. All intermediates remain inspectable. plan$fits and plan$forward are ordinary model lists; plan$scores contains the full candidate table, and plan$worklist and plan$shortfall describe the actual preparation plan. It does not write a file.

Unlike the earlier new-recipe-only scorer call, svem_plan_runs() counts the incumbent repeat within its total budget. Its default five slots can hold one reference repeat plus up to four distinct model optima. This example uses eight total preparations, leaving room for exploration. Optionally retain a fixed original-design benchmark as well: set fixed_benchmark to its unique preparation ID below. That benchmark is mandatory and counts within the total, reducing the slots available for model optima or exploration. It shares one repeat if its physical recipe is also the incumbent; otherwise both repeats must fit in the budget. The default order is the incumbent, elastic-net SVEM, GauPro, Extra Trees, then forward likelihood. A smaller budget truncates that order; with one slot and an enabled incumbent, the plan is confirmation only. Set incumbent = FALSE when every slot must be a new recipe. The priority is a practical allocation rule, not a claim that its ordering is best for every experiment. For this multi-response decision each model maximizes the same weighted desirability of its fitted endpoint means. Desirability stops improving at its declared limits. When several multi-response recipes reach the same combined desirability, they remain exact utility ties and the stable recipe key breaks the tie. Extra predicted improvement beyond a saturated goal is not assigned additional utility. Change the scientific goals explicitly if those differences should matter.

Models endorsing the same new recipe spend one slot and retain all their attributions. Inspect best_ties and new_ties in the nominations. When exact ties are resolved by the same recipe key, a shared nomination is not evidence of independent agreement among the fitted models. Remaining slots are distinct high-spread medoids. An unavailable engine is visible in the diagnostics; it is not silently replaced by another fitted model. The code above uses whichever suggested companion packages are installed.

For this first batch we explicitly carry forward preparation 02SEP22-20. Its original operator was B; the planned repeat uses A. This is a declared incumbent choice across contexts, not an automatic comparison of raw A and B outcomes. Matching RunID keeps the choice stable if the table is reordered. Original measurements and source context remain visible for review. Selecting a noisy winner does not establish that it is the best true recipe; the repeat supplies confirmation evidence. Without an explicit row, the planner chooses the best observed preparation within the requested reference context. A separate fixed benchmark keeps its original selector in plan$policy$benchmark and its source row and context in plan$benchmark, regardless of which preparation becomes the incumbent.

Exploration choices. The portfolio uses diverse medoids from the top tenth of the eligible SVEM spread scores for its remaining slots. SVEM summarizes widths of member-percentile intervals across the three responses. Widths are scaled between their 2nd and 98th percentiles and clipped, which can produce exact ties. Ensemble spread is useful for exploration; it is not automatically calibrated predictive uncertainty.

The diagnostics below also show alternatives: choose the largest combined spread and break ties by fitted desirability, or choose the widest underlying spread. They do not allocate extra preparations in this portfolio. The separate scorer can also nominate the largest latent GP standard deviation for a chosen response; no such slot is reserved by the default portfolio. Extra Trees supplies a mean nominee, with trees varying through randomized splits of the full training rows.

An exact tie is possible even when fitted responses and underlying widths differ substantially. For example, consider a single response with widths 1 through 98, then 105 and 120. The 98th percentile falls below 105, so both of the last two recipes receive a scaled width of 1. If their desirabilities are 0.85 and 0.20, respectively, the practical tie-break chooses the former. The raw-width rule chooses the latter. The tie counts printed above refer to the actual multi-response pool.

Change the budget without refitting

To request specific kinds of runs, set n_optima = 3L, n_explore = 2L in the planner call below and omit budget. This requests three new model candidates, two exploration recipes and the best-observed repeat, for six planned preparations. In this worked run, these fitted models nominate only two distinct new recipes, so the call returns five preparations and reports one unmet model request. Setting incumbent = FALSE removes the repeat from the planned total. Inspect selected counts and unused places before preparing the runs.

Forward likelihood and the relaxed elastic net can emphasize different terms in the same candidate model. Forward’s validation score evaluates each training-fitted Gaussian mean and variance on the validation-weighted copy. The wrapper fits this method for each endpoint as well as the primary SVEM models. The same physical pool, scientific weights and planned operator apply to every nominee.

utility <- function(y) {
  parts <- lapply(endpoints, function(nm) {
    g <- goals[[nm]]
    z <- (y[[nm]] - g$lower_acceptable) / (g$upper_acceptable - g$lower_acceptable)
    if (g$goal == "min") z <- 1 - z
    g$weight * log(1e-6 + (1 - 1e-6) * pmin(1, pmax(0, z)))
  })
  exp(Reduce(`+`, parts) / sum(vapply(goals, function(g) g$weight, numeric(1))))
}
